# Лабораторная работа №6. Серверная часть приложения

**Тема:** Система бронирования рабочих мест (мой вариант из лабораторной №1)

## Что я сделала

Сделала серверную часть сайта на PHP по схеме MVC (модель — вид — контроллер).
Сайт показывает обычные HTML-страницы: главную, список бронирований, одну
запись о бронировании, форму для нового бронирования, список рабочих мест и
одно рабочее место. Данные лежат в двух файлах `storage/bookings.json` и
`storage/workspaces.json` — пока без базы данных, как и было сказано в задании.

## Структура проекта

```
src/
├── public/                       # сюда стучится браузер
│   ├── index.php                 # один файл, через который проходят все запросы
│   └── css/style.css             # стили
├── app/
│   ├── autoload.php              # сам подключает нужные классы
│   ├── helpers.php               # мелкие функции: e(), view(), redirect(), notFound(), config()
│   ├── Core/Router.php           # маршрутизатор — решает, какой адрес к какому контроллеру ведёт
│   ├── Controllers/
│   │   ├── HomeController.php    # главная страница
│   │   ├── BookingController.php # бронирования: список, одна запись, форма, сохранение
│   │   └── WorkspaceController.php # рабочие места: список, одно место
│   ├── Models/
│   │   ├── BookingRepository.php   # читает/пишет storage/bookings.json
│   │   └── WorkspaceRepository.php # читает/пишет storage/workspaces.json
│   └── Views/                    # все HTML-шаблоны
├── routes/web.php                # список адресов и кто их обрабатывает
├── config/app.php                # название сайта
└── storage/                      # файлы с данными
```

Коротко, для чего каждая папка:

| Папка | Зачем |
| --- | --- |
| `public/` | то, что видно из интернета: вход в сайт и стили |
| `app/Controllers/` | принимают запрос, берут данные, выбирают, какую страницу показать |
| `app/Models/` | достают и сохраняют данные |
| `app/Views/` | сами страницы (HTML с кусочками PHP) |
| `app/Core/` | маршрутизатор |
| `routes/` | список адресов |
| `config/` | настройки |
| `storage/` | файлы с данными |

## Как запустить

```bash
cd lab6/src
php -S localhost:8000 -t public
```

Дальше открыть в браузере `http://localhost:8000`.

## Какие адреса есть

| Метод | Адрес | Кто обрабатывает | Что показывает |
| --- | --- | --- | --- |
| GET | `/` | HomeController → index | главная со статистикой |
| GET | `/bookings` | BookingController → index | список бронирований, можно отфильтровать по `?status=` |
| GET | `/bookings/create` | BookingController → create | форма нового бронирования |
| POST | `/bookings` | BookingController → store | принимает форму и сохраняет запись |
| GET | `/bookings/{id}` | BookingController → show | одна запись о бронировании |
| GET | `/workspaces` | WorkspaceController → index | список рабочих мест |
| GET | `/workspaces/{id}` | WorkspaceController → show | одно место и его бронирования |

`/bookings/create` стоит в списке раньше `/bookings/{id}`, иначе слово "create"
маршрутизатор принял бы за номер бронирования.

## Моя предметная область (шаг 5)

Я сразу делала проект под свою тему — бронирование рабочих мест, без примера
"задачи/проекты".

| Что надо было определить | Что получилось |
| --- | --- |
| Основная сущность | бронирование (booking / bookings) |
| Связанная сущность | рабочее место (workspace / workspaces) |
| Поля бронирования | id, workspace_id, employee_name, status, time_slot, booking_date |
| Поле для фильтра | status: new (ждёт подтверждения), confirmed (подтверждено), cancelled (отменено) |
| Поля рабочего места | id, title, description (где находится и какое) |

Что я поменяла по сравнению с примером "задачи/проекты":
- TaskController и ProjectController стали BookingController и WorkspaceController, то же с моделями и шаблонами.
- Вместо названия задачи — ФИО сотрудника, кто бронирует (`employee_name`).
- Вместо приоритета (низкий/средний/высокий) — время (`time_slot`: утро/день/весь день).
- Вместо срока выполнения — дата бронирования (`booking_date`).
- Вместо статусов "новая/в работе/выполнена" — "ждёт подтверждения/подтверждено/отменено", потому что это больше похоже на то, как живёт бронирование.
- `project_id` стал `workspace_id`, а метод `byProject()` — `byWorkspace()`.

Проверила ещё раз все адреса из таблицы выше, но уже на своих — коды ответов
совпали. Старых адресов `/tasks` и `/projects` в проекте теперь нет.
